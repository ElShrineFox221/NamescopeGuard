# 提交规范

> 适用范围：本仓库的 git 提交。
> 定位：提交时机、commit message 格式与用词的**唯一标准**。

---

## 1. 时机与授权

- 仅在用户明确要求时提交；内容确认 / 认可不等同于提交授权。
- 提交后不 push（除非另有指令）。

## 2. 消息格式

- **单行**：`<type>: <简述>`；`type` 为小写英文缩写（见下「类型」）；`简述` 用中文、一行内说清提交方向；**不使用内部编号**。

## 3. 类型

| 缩写 | 范围 |
|---|---|
| `feat` | 新功能 / 新实现 |
| `fix` | 缺陷修复 |
| `refactor` | 重构（行为不变） |
| `perf` | 性能优化 |
| `test` | 测试 |
| `docs` | 文档 / 规范 |
| `build` | 构建 / 依赖 / 项目配置 |
| `chore` | 杂务（清理等） |
| `revert` | 回滚 |
| `style` | 纯格式 / 命名风格等不影响语义的调整 |
| `ui` | UI / 表现（界面 / 主题 / 字体 / 场景 / 美术资源等） |
| `i18n` | 翻译文本 / 本地化 |

## 4. 语言与术语

- 消息本身用中文；代码对象名**原名优先**（保留代码中的实际标识符）；专业名词**英文原词优先**；**项目既有概念优先**。
- 示例：`build: 集中配置 LangVersion 与 Nullable`、`docs: 提交规范独立成文`、`chore: 移除模板占位类`。
