# 代码注释规范与审查方法

> 适用：本仓库 C# 源码注释（尤其 XML 文档注释）。
> 定位：注释相关规范的**唯一标准**；`code-conventions.md` C7 指向本文。
> 编写规范见 `docs/writing-conventions.md`。

---

## 1. 规范

- **注释最小化**：只注释**命名无法体现**的信息（契约 / 前置条件 / 单位 / 边界 / 副作用等）。
- **命名优先于注释**：能以更准确的命名消除注释的，改命名而非加注释。
- **不复述**代码、名称，或已由背景文档给出的专有名词。
- **原词优先**：提及已有英文名的类型 / 成员，用 `<see cref="..." />` 引用（或直接写英文名），不另造中文译名。
- 公共 API 的 XML 文档同样遵循最小化。

## 2. 核心方法

对每个元素，先问「**它本身是什么**」，据此写出最基本的一句话注释，再判断必要性：

- 与**名称 / 签名 / 类型形状**重复 → 删除。
- 只保留读者**推不出**的信息。

## 3. 保留判据

仅当注释承载以下**推不出**的信息时保留：

- 契约 / 前置 / 后置条件。
- 单位、取值范围、边界（如「从 1 起、不回收」「0 不作有效值」）。
- 副作用（如修改全局状态、离开作用域时隐式清理）。
- 非自明的角色 / 边界（如抽象基类的职责、排除范围）。

## 4. 删除判据

- 复述类型 / 成员 / 枚举项 / 字段 / 参数名称。
- 复述签名 / 返回类型已表达的行为。
- 描述**别处**负责的规则 / 行为（如把调用方规则写进被调用类型、把消费者用法写进被消费类型）。
- 对类名的机械直译（见 `writing-conventions.md` §I「不硬译 / 原词优先」）。

## 5. 逐元素要点

- **枚举**：只表「这组取值是什么」；不写使用规则。
- **record / 值类型**：字段自明时不加注释。
- **类 / 抽象基类**：可留一句**角色**；成员能推出作用时不展开。
- **方法**：只在有隐含契约 / 副作用时注释（隐式上下文、环境状态变更）。
- **异常**：名字已表意时不加；必要时只写**抛出时机**。

## 6. 示例

- 删：某枚举注释写「调用方按此值路由到对应处理器；不得跨层复用」——是**调用方的路由规则**（属设计文档），非枚举自身语义；枚举含义与名 + 成员重复。
- 留：`EntityId` 注释「从 1 起、不回收，0 不作有效值」——分配契约，推不出。
