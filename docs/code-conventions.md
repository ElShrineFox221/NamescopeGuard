# 代码规范

> 适用范围：本仓库全部 C# 代码及相关工程配置。
> 定位：代码书写与组织的统一约定（**写码前必读**）。

---

## C1 · 语言与编译

- 统一启用 preview 语言特性、可空引用类型与确定性编译（由 `Directory.Build.props` 集中设定）。

## C2 · 可空与 null 校验

- 依赖**可空标注 + 静态分析**保证；**默认不手写运行时参数 null 校验**。
- **仅**在以下情形显式校验：反射式调用；调用**不遵循可空规范**的 API / 三方库；**外部数据边界**（反序列化 / 配置 / 原生互操作）。
- **领域校验**（如空字符串、非法取值、范围）不属于 null 校验，仍应保留。

## C3 · 语法糖

- 在**不牺牲清晰度与封装**的前提下优先使用：主构造函数、属性 `field` 关键字、目标类型 `new`、集合表达式 `[]`、表达式体成员、模式匹配等。
- 存在陷阱（如 primary 构造函数捕获语义、可变性、封装泄漏）时不强行使用。

## C4 · 代码折叠（region）

- `override` 成员使用 `#region Overrides`（含 `Equals` / `GetHashCode` / `ToString`）。
- 运算符（含 `implicit` / `explicit` 转换）使用 `#region Operators`。

## C5 · 命名空间

- 一律使用**文件级命名空间**（file-scoped），并由 `.editorconfig` 强制。
- 命名空间与目录结构一致。

## C6 · 空块与花括号

- **不写跨多行的空花括号**；无成员体优先省略花括号（如主构造函数类型、无成员类以 `;` 收尾）。
- 语法确需的空块（空方法 / 空访问器）写为**单行** `{ }`，不跨行展开。

## C7 · 注释

- 注释相关规范与审查方法见 `docs/code-comment-review.md`（**唯一标准**）。

## C8 · 异常

- **模块归属**：同命名空间抛出的异常，类型名携带所属命名空间 / 模块信息（如统一基类以模块名 + `Exception` 命名），便于从异常名识别来源。
- **统一基类（按需）**：模块存在多条异常时，设统一基类作为该类异常的**统一捕获入口**，具体异常由其派生；仅单一异常时不设中间基类（**聚合**场景例外，见下）。
- **统一根与分级**：异常经统一根异常派生，暴露 `ExceptionLevel`（`Fatal` / `Error` / `Warning`）供顶层 / 日志按级处置；根默认 `Error`，分支按需 override。中间分支**按需增设**——仅当存在明确区分逻辑且不止一条时才在根与模块基类间插入。
- **框架异常**：模块异常自带语义，**不必**为此内嵌对应框架异常（如「未找到」直接由模块异常表达即可）；**聚合**场景可直接外抛 `AggregateException`（`InnerExceptions` 承载具体失败）。
- **物理组织**：同一命名空间存在**多个**异常时，集中于单个 `Exceptions.cs`；仅有一个异常时，可直接以该异常类名命名文件；文件内出现多条分支时以 `#region` 分隔。

## C9 · 常量

- 有跨层调整意义的常量（未来会由数据 / 配置层等接管的默认值）统一集中到项目级默认值类型（开发阶段临时）；默认空字符串、`nameof` 计算字符串等确定不跨实现层的内容不在此列。
- `const` 常量统一采用**大写 + 下划线**（UPPER_SNAKE_CASE）命名。
